# 필요한 만큼 공식 출처 확인

[작업 지침](../../AGENTS.md)과 [핵심 규칙](../../RULES.md)을 따른다.

## 언제 사용하는가

외부 API 계약, 버전·모듈 지원, 플랫폼 호환성, 요금·자원 조건이 불확실하거나 변경될 때 사용한다. 기존 Wiki에 확인한 근거가 있고 적용 버전·조건이 같다면 재사용한다. 매 작업마다 최신 자료 전체를 조사하지 않는다.

## 절차

1. 이번 판단에 필요한 질문과 대상 버전·리비전·환경만 좁힌다.
2. 공식 문서나 공식 저장소의 관련 부분을 확인한다. 검색 요약·제3자 예시는 탐색 단서이지 실제 지원의 증거가 아니다.
3. 문서에 명시된 지원, 소스에서 확인한 구현, 실제 실행 결과를 구분한다. 문서만 확인했다면 연동 성공으로 보고하지 않는다.
4. 실행이 요청 범위에 포함되면 해당 경로의 작은 시나리오로 확인한다. 외부 계정·설치·운영 변경·삭제의 승인 범위를 우회하지 않는다.
5. 결론에 공식 URL·확인한 버전/환경·미확인 조건을 남긴다. 장기 재사용 가치가 있고 문서 수정이 허용된 경우에만 `llm-wiki`로 기존 주제를 갱신한다. 사소한 조회마다 이력을 만들지 않는다.

## Picksy에서 구분할 것

- 추론 엔진의 모델·응답·score·confidence 의미와 OMP가 요구하는 계약. 엔진별 계산 의미를 확인하며 서로 같다고 가정하지 않는다.
- Caddy 기본 기능과 별도 모듈, DNS 탐색과 실제 준비 상태·분산.
- Compose 복제와 자동 롤링 업데이트. 설정 존재와 요청 중 교체 성공.
- amd64 실행과 arm64 동작·성능, Oracle 상품 설명과 실제 VM 자원·비용 조건.

자료에 없는 날짜·버전·지원 범위를 추정하지 않는다. 접근할 수 없는 자료는 미확인으로 남기되 관련 없는 구현까지 막지 않는다. 확인된 근거와 보수적인 선택으로 진행 가능한 부분은 계속 진행하고, 제품 범위나 보안 경계를 바꾸는 선택만 사용자에게 확인한다.

지침 문구 변경은 현재 세션에서 파일을 읽고 바로 적용한다. 도구 등록·실제 설정 재로딩이 필요한 경우가 아니라면 새 세션을 요구하지 않는다.
