## 배경과 결정

AI 판단 API를 제공하는 자체 호스팅 서비스의 초기 구성·DB·배포 방향을 합의했다. 각 기술 선택의 현재 내용은 연결된 주제 문서가 원본이며 여기서 복제하지 않는다.

## 대안과 선택 이유

- Gateway와 Laya의 1:1 결합 대신 독립 풀을 선택했다. 복제본 개수만 조절해 확장하는 운영 목표가 인계에 포함되어 있다. 더 상세한 비교 평가는 미기록이다.
- 로컬 DB를 운영으로 복사하지 않고 운영 데이터를 별도로 유지한다. Migration과 승인된 배포에서 데이터 변경을 관리한다.
- Docker MCP 도입은 보류하고 CLI를 사용한다. 당장 MCP가 불필요하다는 판단 외 상세 비교 근거는 미기록이다.
- Rust·Axum, Caddy, SQLite, Oracle VM 등 개별 기술의 대안별 비교·정량 근거는 인계에 없어 사후에 만들어 기록하지 않는다.

## 결과·단점·검증 상태

설계는 단일 VM 장애를 해결하지 않는다. Compose 롤링 교체 절차와 DB 변경의 안전성은 별도 구현이 필요하다. Laya의 품질·ARM 성능·OMP 실제 연동과 풀 탐색·준비 상태·분산은 미검증이다.

앱·Docker 설정은 미구현 상태로 인계됐다. OMP 소스 지원 확인과 Docker 설치 관측은 사용자 보고이며 이번 기록의 실행 증거가 아니다. 세부 확인 과제는 각 현재 문서에 유지한다.
